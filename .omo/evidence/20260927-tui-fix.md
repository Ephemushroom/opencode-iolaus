## Live TUI

Commands run in the task worktree:

```sh
node script/qa-tui.mjs .omo/evidence/20260927-tui-release-light
IOLAUS_QA_THEME=dark node script/qa-tui.mjs .omo/evidence/20260927-tui-release-dark
```

Both passed. Each run exercised a real OpenCode TUI in a dedicated tmux
server, isolated HOME/XDG directories, and a local mock provider. Assertions
covered the running node, review/revision sequence, waiting gate, approval
through the TUI RPC, completion, opening a node session, and returning to the
owner session without another DAG event. A node session does not inherit the
owner's DAG permissions.

ANSI captures verify actual foreground colors, not just stripped text:

- Light title: RGB(26, 26, 26); empty-state text: RGB(138, 138, 138).
- Dark title: RGB(238, 238, 238); empty-state text: RGB(128, 128, 128).
- Live light-to-dark and dark-to-light switches changed the mounted sidebar
  text to the expected mode's color.

The same harness against the unchanged main checkout's old build failed with
`Iolaus DAG has no explicit RGB foreground (the original flat-theme bug)`.
See [the negative-case output](20260927-tui-release-red.log).

Receipts and selected ANSI captures are retained in
[light](20260927-tui-release-light/receipt.json) and
[dark](20260927-tui-release-dark/receipt.json). Full local tmux logs and
intermediate captures are intentionally not included in this change.

## Multi-location RPC

```sh
bun script/qa-tui-routing.mjs .omo/evidence/20260927-tui-release-routing
```

PASS. One isolated real OpenCode server loaded two project locations. A mock
agent called `iolaus_dag create` in each. The negative case omitted location
when querying project B's owner and returned an empty list. The production
query helper with explicit location found the correct DAG in both projects.
Approval routed to B completed only B's gate; A remained paused. Querying B's
owner through A's location returned no unrelated runs.

All positive receipts assert unchanged hashes of the real host's config and
database and removal of the QA sandbox. The routing receipt also confirms its
server exited. No credentials, host session contents, or global configuration
changes are included.

This change does not migrate DAG storage or change controller recovery after
plugin reload.
